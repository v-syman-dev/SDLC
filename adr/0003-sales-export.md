# ADR-0003. Проданные билеты выгружаются в CSV по мероприятию

## Контекст и постановка задачи

Во втором раунде заказчику понадобился список проданных билетов для сверки мест. Дата выпуска 11.12.2026 и лимит 3 300 BYN фиксированы. Новый модуль требуется развивать параллельно, с интеграцией после появления первого сценария продажи.

## Драйверы решения

- SYS-F06 требует скачиваемый файл по одному мероприятию.
- SYS-N02 требует проверку роли и принадлежности события до получения данных.
- Выгрузка содержит номера билетов, расположение мест и время продажи. Данные покупателей исключаются из запроса.
- Допустим ограниченный объём первой версии, согласованный с заказчиком.

## Рассмотренные варианты

- Таблица продаж в интерфейсе.
- Асинхронная генерация файла с очередью и хранилищем.
- Синхронный CSV со снимком данных и лимитом строк.

## Итог решения

Выбран «Синхронный CSV со снимком данных и лимитом строк». Отдельный модуль SalesExport читает выпущенные билеты из PostgreSQL по событию, принадлежащему организатору. В первой версии выгружается до 10 000 билетов. Формат и авторизация проектируются независимо от платёжной саги, поэтому часть работы можно выполнить параллельно на фикстурах. Подключение к данным продажи выполняется в третьей итерации.

### Последствия

- Новый контракт не меняет транзакции удержания и продажи.
- Доступ к файлу определяется сервером. Поля выбираются по списку, а формат кодов сектора ограничен буквами ASCII и цифрами.
- Синхронное формирование занимает ресурсы экземпляра API. При 10 001 строке и выше API сообщает о превышении лимита до начала отправки файла.
- Привлечение младшего разработчика сохраняет дату выпуска. Старший выполняет ревью доступа и контракта.

### Подтверждение

Интеграционные тесты проверяют выгрузку своего события, отказ для чужого, файл с одними заголовками без продаж, состав и порядок полей, отсутствие персональных данных и лимиты 10 000/10 001 строка. CSV должен совпадать с набором выпущенных билетов на момент SQL-снимка.

## Плюсы и минусы вариантов

| Вариант | Плюсы | Минусы |
|---|---|---|
| Таблица продаж в интерфейсе | Просмотр и фильтрация в приложении | Не даёт заказчику отдельный файл для сверки, требует разработки таблицы и фильтров |
| Асинхронная генерация файла с очередью и хранилищем | Подходит для больших выгрузок и повторного скачивания | Нужны очередь, управление сроком хранения и отдельные проверки прав на скачивание |
| Синхронный CSV со снимком данных и лимитом строк | Простой контракт, готовый результат в одном запросе, работу можно начать с тестовых данных | Размер ограничен для защиты времени отклика и памяти API |
